The most difficult concept in the course was managing high-concurrency race conditions during flash-sale scenarios—specifically implementing distributed locking and multi-tiered transactional consistency. Understanding how to handle thousands of concurrent write requests per second without encountering database row lock contention or overbooking seats required a shift from standard CRUD logic to decoupled architecture principles. I overcame this by studying optimistic concurrency control patterns, using Redis single-threaded execution for atomic locks before touching the relational database, and testing edge cases with high-load query simulations.

Based on capstone feedback, the primary area I would improve in my TicketHub system is the resilience of the virtual waiting room queue and cache invalidation pipeline. While the core database schema successfully prevented double-booking through conditional updates, introducing a more robust retry mechanism for expired Redis holds and refining the asynchronous event queue during peak worker failures would make the system more production-ready under unpredictable network spikes.

Moving forward, I plan to dive deeper into system scaling architectures, database indexing strategies, asynchronous queue decomposition, and microservices design. Specifically, I want to explore high-concurrency web services built with Go, event-driven streaming with Apache Kafka, and advanced Kubernetes orchestration for auto-scaling microservices under heavy load.
